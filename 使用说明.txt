侵权链接处置核验工具 - 使用说明
================================

当前版本：3.13.0

本说明只讲安装和操作。工具如何判定、各平台规则、证据优先级和可能遗漏的情况，请看同目录《核验逻辑说明.txt》。

从 GitHub 获取源码时，可直接双击“启动工具.cmd”。首次运行会从微软官方 NuGet 下载固定版本的 WebView2 SDK，在本机自动编译后启动；后续运行会直接打开程序。首次准备需要网络连接，正常使用仍建议优先采用已经打包好的便携版。


一、发给别人时怎么做
--------------------

1. 只发送“便携版”目录中的“链接失效核验工具_便携版.zip”，不要单独发送 exe。
2. 对方必须先完整解压 ZIP，建议解压到本机“文档”或桌面下的普通文件夹。
3. 不要在压缩包里直接双击，不建议放在网络盘、U 盘、Program Files 或其他受保护目录中运行。
4. 解压后双击“启动工具.cmd”。启动检查器会自动选择 32 位或 64 位程序，并生成“启动检查报告.txt”。
5. 正常使用不需要管理员权限，也不要求电脑安装 Microsoft Office。

便携包应包含：
- 启动工具.cmd
- StartupCheck.exe
- 使用说明.txt
- 核验逻辑说明.txt
- 运行环境与网络诊断.cmd
- 诊断链接.txt
- x64 文件夹
- x86 文件夹

缺少其中的程序文件时，不要从其他版本中零散复制，请重新完整解压便携包。


二、电脑兼容范围
----------------

正式适配：
- Windows 10、Windows 11
- 32 位和 64 位 Windows
- .NET Framework 4.6.2 或更高版本，建议 4.8/4.8.1
- 低配置电脑可使用“自动适配”或“低配模式”

快速核验：
- 不依赖 Excel 安装
- 不依赖 WebView2 Runtime
- 有 Edge 或 Chrome 时，少数动态平台可获得额外的无界面网页证据

浏览器深度复核：
- 需要 Microsoft Edge WebView2 Runtime
- Windows 10/11 和正常更新的 Microsoft Edge 通常已经包含
- 未安装 WebView2 时，快速核验仍然可以使用

未作为正式支持环境：
- Windows 7、Windows 8/8.1
- ARM64 Windows
- macOS、Linux
- 被单位安全策略禁止普通程序联网的电脑

这些环境可能仍能启动，但不能保证所有功能和平台都可用。


三、基本使用流程
----------------

1. 双击“启动工具.cmd”。
2. 点击“选择 Excel / CSV”，选择待核验文件。
3. 点击“开始核验”。这里开始的是快速核验，不会自动进入深度复核。
4. 快速核验完成后查看三种结果：已失效、仍可访问、人工复核。
5. 需要继续处理候选项时，手动点击“启动后台复核候选项”。
6. 如果已配置 Yunwu API，可再点击“AI 辅助复核”，处理有正文证据但机器规则仍无法确认的候选项。
7. 确认结果后，再手动点击“写回原 Excel”或“导出结果”。

Excel/CSV 会自动识别以下常见表头：
- 链接、URL
- 标题
- 摘要、内容摘要、正文摘要
- 账号昵称、作者、发文作者、发布账号、发布人、发布者、账号名称、昵称、账号
- 平台、内容类型等辅助字段

支持 .xlsx、.xlsm、CSV。旧版 .xls 请先另存为 .xlsx。


四、中断、停止和继续
--------------------

1. 每完成一条，工具都会把结果写入断点进度。
2. 点击“停止”、关闭程序、电脑重启或意外中断后，已经完成的结果会保留。
3. 重新启动后点击“继续上次核验”，只补跑未完成的链接。
4. 版本升级后，已经确定的“已失效/仍可访问”会保留；旧版待复核、异常和疑似项会按新规则重新核验。
5. 断点进度优先保存在当前用户的 LocalAppData。该目录不可写时，工具会尝试用户文档或临时目录。

注意：临时目录可能被系统清理。若启动检查报告显示 LocalAppData 不可写，建议把报告交给电脑管理人员处理权限问题。


五、深度复核和登录
------------------

1. 快速核验结束后不会自动深度复核，必须由使用者手动启动。
2. 深度复核窗口会先列出可能涉及的平台登录入口。
3. 登录是可选项，不是开始按钮的前提。微博、抖音、知乎、雪球等会先检查公开页面状态。
4. 需要登录时，可以先选择平台并登录，然后点击右下角“开始后台复核（登录可选）”。
5. 开始后窗口会自动最小化，按平台分批处理，不需要盯着网页或逐条点击“跳过”。
6. 验证码、风控和临时网络错误不会被当作已失效，也不会再混写为“人工复核”；界面会标为“暂时异常”。
7. 连续 8 条出现 502、444、429、验证码、超时或连接失败时，工具会自动熔断并保存进度，避免把整批链接继续刷成待复核。
8. 链接达到 20 条时，工具会先从不同平台抽取最多 8 条进行网络预检；若多数样本都是临时网络异常，会让使用者选择“仍然继续”或“保存并暂停”，不会再强制阻止整批开始。
9. 正式核验中，同一平台连续 3 条受到网络限制时只暂停该平台，其他平台继续处理；未处理链接保留在断点中。
10. 点击“继续上次核验”时，原有“暂时异常”会自动重新检查；已经确认的“已失效/仍可访问”不会重复请求。


六、结果含义
------------

已失效：取得了目标内容当前已经删除、不存在、下架、私密不可见或进入已验证错误页的强证据。

仍可访问：当前页面、官方内容页或可靠公开接口能够确认目标内容编号及正文/摘要/作者等身份，目标内容仍存在。

暂时异常：当前网络出口或目标站点返回 502、444、429、验证码、超时等临时限制；应稍后重试，不代表需要逐条人工核验。

人工复核：自动证据不足、证据冲突、需要登录/App、通用网页外壳或未知平台暂时无法自动确认。

“人工复核”不等于已失效，也不等于仍可访问。

AI 辅助复核是可选的二次阅读层，不是第四种最终结果。表格中的“AI建议”用于审计模型意见；最终写回仍只有“是、否、待复核”。

写回 Excel 时只写一列“链接是否失效”：
- 已失效 -> 是
- 仍可访问 -> 否
- 人工复核 -> 待复核


七、Excel 写回与结果保存
----------------------

1. 工具核验过程中不会自动修改原 Excel。
2. 写回前请关闭 Excel 中正在打开的原文件。
3. 写回前会在原文件同目录创建“文件名_核验前备份_时间.xlsx”。
4. 如果原 Excel 所在目录不可写，写回会失败，需要把文件移动到有权限的位置。
5. 直接粘贴链接、导入 TXT 或仅需独立结果时，使用“导出结果”保存 CSV。
6. 超过 5,000 条时，界面只显示性能模式允许的前一部分记录；断点、写回和导出仍包含全部结果。
7. CSV 导出会额外保留 AI 建议、AI 置信度和 AI 模型，便于抽查；这些字段不会改变原 Excel 的列结构。


八、性能模式
------------

自动适配：根据进程位数、CPU 核心数和物理内存选择保守并发，并对容易触发安全验证的平台按域名限速。建议保持此选项。

低配模式：1 个并发、较小页面读取量、较少表格显示行，适合低配置电脑、单位网络或已经出现平台风控时使用。

标准模式：3 个并发，适合常见办公电脑。

高性能模式：6 个并发，只适合配置较高且平台分布较分散的任务。单位网络限速或站点风控明显时，不建议使用。

工具会把同一平台的请求按最短间隔排队，HTTP 429 不会立即换线路重试；深度复核一旦看到安全验证、访问频繁或验证码，会暂停本批该平台的剩余链接。暂停项不会丢失，可在平台冷却后继续。即使使用高性能模式，也不会绕过验证码或平台安全机制。


九、常见问题
------------

1. 双击后没有主界面
   查看“启动检查报告.txt”。若报告提示文件缺失、.NET 版本过低或从压缩包临时目录运行，按报告处理后重试。

2. 所有 HTTP/HTTPS 都显示连接失败
   双击“运行环境与网络诊断.cmd”。报告会分别测试系统代理和直连。若两条路线都被拒绝，通常是安全软件、代理白名单或单位网络策略，不是失效识别规则问题。

3. 快速核验能用，深度复核打不开
   查看启动检查报告中的“Edge WebView2 Runtime”。未检测到时安装或修复 WebView2 Runtime。

4. Excel 写回失败
   关闭 Excel，确认文件不是只读，确认所在目录有写权限后重试。

5. 某个平台突然大量进入人工复核
   可能是平台改版、接口变化、验证码、账号风控或网络拦截。不要把这批记录直接视为已失效，请保留结果和诊断报告用于更新规则。

6. 程序异常退出
   工具会在用户数据目录或桌面生成“运行异常报告_时间.txt”。重新打开后先点击“继续上次核验”，再把报告交给维护人员。

7. 怎么使用 Yunwu AI 辅助复核
   先点击“AI 设置”，在本机输入 Token，点击“读取模型”，选择一个支持 Chat Completions 的模型，再点击“测试并保存”。完成正常核验或后台复核后，点击“AI 辅助复核”。每次最多处理 100 条符合安全条件的候选，并在发送前再次显示数量和数据范围。

8. 为什么 AI 没处理某些人工复核
   网络异常、验证码、登录页、App 限制、403/429、页面摘要不足和已经确定的结果不会发送给 AI。旧版本断点没有保存页面摘要时，请用当前版本重新核验候选项。

9. AI 能不能解决网站风控
   不能。AI 只阅读工具已经取得的页面证据，不会绕过验证码、登录、平台权限或单位网络限制。遇到这些问题，应等待平台冷却、换用合规登录会话或由人工确认。

10. 怎样把执行情况发给维护人员分析
    每次快速核验、浏览器快速复核、后台深度复核或 AI 辅助复核结束时，工具都会生成独立执行日志。点击主界面的“查看执行日志”会打开最新一份。

    日志包含工具版本、运行编号、开始/结束时间、执行结果、任务数量、结果和 HTTP 状态分布、平台/域名汇总、AI 使用量、中断原因、匿名问题样本和自动诊断提示。

    日志不包含 API Token、Cookie、登录账号、完整网页正文或完整链接。问题样本使用匿名链接 ID，并对短原因中的链接、凭据、邮箱和用户目录做脱敏。发送前仍应按所在单位要求检查内容。

    默认日志目录位于当前用户数据目录的 LinkDispositionChecker\RunLogs；“最近一次执行日志.txt”始终指向最近结束的一次任务。反馈时优先发送这个文件，并补充说明你认为最影响使用的现象。


十、数据安全
------------

工具在本地运行，不会把导入的工作簿或整批链接上传到本工具自己的服务器。
核验时会从当前电脑直接访问目标平台及其公开内容页/公开接口，这是完成核验所必需的网络访问。
启动检查报告不包含导入文件内容、待核验链接、Cookie、账号、密码、IP 或代理地址。

AI 辅助复核默认不启用。只有使用者主动配置并确认后，工具才会把候选记录的链接、标题、作者、HTTP 状态、机器判定依据，以及最多约 6500 字的当前可见正文摘要发送到所配置的 Yunwu API。不会发送 Cookie、登录账号、浏览器凭证或完整 Excel。

API Token 使用 Windows 当前用户的数据保护机制加密，保存在本机用户数据目录，不写入程序目录、导出结果或 Git 仓库。Token 只能由同一 Windows 用户在本机解密。Yunwu 是第三方 API 服务，发送的数据会受其服务条款、隐私政策和账户计费规则约束；处理敏感或受保密要求的数据前，应先确认所在单位允许使用该服务。


十一、当前验证基线
----------------

固定代表样本：1200 条。
3.13.0 建立可重复的执行日志与版本迭代闭环。快速核验、浏览器复核、后台复核和 AI 复核结束后自动记录运行编号、结果分布、网络/平台状态、AI 使用、中断原因和匿名失败样本，并在主界面提供“查看执行日志”。
3.12.2 修复 AI 设置在部分 Windows/单位网络中因 TLS 1.2 和系统代理凭据未初始化而始终连接失败的问题；AI 客户端现在与主核验模块使用一致的 Windows 网络设置，并提供更明确的连接错误提示。
3.12.1 修复网络预检反复强制终止整批、导致“继续上次核验”始终无法开始的问题。预检异常时改由使用者决定是否继续；选择继续后只暂停持续受限的平台，并把代理/直连重试总时长限制为 18 秒。
3.12.0 增加可选的 Yunwu AI 辅助复核、本机加密 Token、模型读取、发送前确认、AI 审计字段和本地安全门。AI 只处理已有当前正文证据的候选，不处理验证码、登录或网络异常；AI 的“已失效”建议不会单独形成确定结论。
3.11.0 增加跨平台小样本网络预检、平台独立熔断和部分完成提示，避免一个受限平台拖累整批任务。
3.10.7 将网络/风控结果与真正的人工复核分开显示，并在连续 8 条出现限流、验证码或网络异常时自动熔断、保存进度。
3.10.6 增加平台级请求排队、保守并发、HTTP 429 停止即时重试，以及安全验证后的同平台批次暂停，以减少连续批量核验触发风控。
3.10.5 当前网页基线：已失效 624、仍可访问 519、人工复核 57，人工复核率 4.75%。

这个 4.75% 是固定样本在 2026-07-24 的“人工复核比例”，不是对所有未来数据承诺 95.25% 准确率。平台、网络环境、链接类型和网页状态变化都会影响实际结果。
