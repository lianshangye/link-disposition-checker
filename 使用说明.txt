侵权链接处置核验工具 - 使用说明
================================

当前版本：4.2.0

本说明只讲安装和操作。工具如何判定、各平台规则、证据优先级和可能遗漏的情况，请看同目录《核验逻辑说明.txt》。

从 GitHub 获取源码时，可直接双击“启动工具.cmd”。首次运行会从微软官方 NuGet 下载固定版本的 WebView2 SDK，在本机自动编译后启动；后续运行会直接打开程序。首次准备需要网络连接，正常使用仍建议优先采用已经打包好的便携版。


一、发给别人时怎么做
--------------------

1. 只发送“便携版”目录中的“链接失效核验工具_便携版.zip”，不要单独发送 exe。
2. 对方必须先完整解压 ZIP，建议解压到本机“文档”或桌面下的普通文件夹。
3. 不要在压缩包里直接双击，不建议放在网络盘、U 盘、Program Files 或其他受保护目录中运行。
4. 解压后双击“启动工具.cmd”。启动检查器会自动选择 32 位或 64 位程序，并生成“启动检查报告.txt”。
5. 正常使用不需要管理员权限，也不要求电脑安装 Microsoft Office。

便携包应包含：
- 启动工具.cmd
- StartupCheck.exe
- 使用说明.txt
- 核验逻辑说明.txt
- 运行环境与网络诊断.cmd
- 诊断链接.txt
- x64 文件夹
- x86 文件夹

缺少其中的程序文件时，不要从其他版本中零散复制，请重新完整解压便携包。


二、电脑兼容范围
----------------

正式适配：
- Windows 10、Windows 11
- 32 位和 64 位 Windows
- .NET Framework 4.6.2 或更高版本，建议 4.8/4.8.1
- 低配置电脑可使用“自动适配”或“低配模式”

快速核验：
- 不依赖 Excel 安装
- 不依赖 WebView2 Runtime
- 有 Edge 或 Chrome 时，少数动态平台可获得额外的无界面网页证据

浏览器深度复核：
- 需要 Microsoft Edge WebView2 Runtime
- Windows 10/11 和正常更新的 Microsoft Edge 通常已经包含
- 未安装 WebView2 时，快速核验仍然可以使用
- 界面中的“内置浏览器”指 WebView2 内核，并不是强制打开 Edge 浏览器

未作为正式支持环境：
- Windows 7、Windows 8/8.1
- ARM64 Windows
- macOS、Linux
- 被单位安全策略禁止普通程序联网的电脑

这些环境可能仍能启动，但不能保证所有功能和平台都可用。


三、基本使用流程
----------------

1. 双击“启动工具.cmd”。
2. 点击“选择 Excel / CSV”，选择待核验文件。
3. 点击“开始核验”。4.2 会自动完成基础核验、本机多线路、无缓存公开云取证、必要的浏览器复核、AI 收尾和验收证据包生成。
4. 核验结束后分别查看“内容状态”“公开可访问性”“合同验收建议”。不要把自动多线路访问失败直接当作内容删除。
5. “重新运行后台追证”只用于主动重跑仍有歧义的候选，正常流程不需要手动启动。
6. 已配置 Yunwu API 时，工具会自动处理已经取得正文但机器规则仍无法确认的候选；网络错误页不会发送给 AI。
7. 确认结果后，再手动点击“写回原 Excel”或“导出结果”。
8. 本次任务完成后会在结果目录生成“验收证据包”。也可以点击“生成验收证据包”重新生成。

Excel/CSV 会自动识别以下常见表头：
- 链接、URL
- 标题
- 摘要、内容摘要、正文摘要
- 账号昵称、作者、发文作者、发布账号、发布人、发布者、账号名称、昵称、账号
- 平台、内容类型等辅助字段

支持 .xlsx、.xlsm、CSV。旧版 .xls 请先另存为 .xlsx。


四、中断、停止和继续
--------------------

1. 每完成一条，工具都会把结果写入断点进度。
2. 点击“停止”、关闭程序、电脑重启或意外中断后，已经完成的结果会保留。
3. 重新启动后点击“继续上次核验”，只补跑未完成的链接。
4. 版本升级后，已经确定的“已失效/仍可访问”会保留；旧版待复核、异常和疑似项会按新规则重新核验。
5. 断点进度优先保存在当前用户的 LocalAppData。该目录不可写时，工具会尝试用户文档或临时目录。

注意：临时目录可能被系统清理。若启动检查报告显示 LocalAppData 不可写，建议把报告交给电脑管理人员处理权限问题。


五、深度复核和登录
------------------

1. 开始核验后会自动识别域名背后的共享 IP/基础设施，避免把同一服务器上的大量域名并发访问。
2. 502、超时和连接失败会自动继续尝试：清理分享参数、系统代理/直连、同站首页对照、平台公开入口、内置无缓存公开云取证，以及已配置的独立远程取证节点。
3. 同站首页可以访问但目标页异常时，会自动进入浏览器追证；整个基础设施异常时不会反复刷新数百次。
4. 同一基础设施连续 3 条完成追证仍失败时，剩余链接会生成完整的可重试结果，不再出现“导入 985 条但只有 560 条结果”。
5. 网络预检只用于安排调度和记录诊断，不再弹窗要求决定是否暂停，也不会全局中断其他站点。
6. 浏览器候选自动启动、自动最小化并连续处理；需要主动登录或重新尝试时，仍可点击“重新运行后台追证”。
7. 验证码、风控和临时网络错误不会被当作已失效；只有当前目标页、官方接口或远程节点取得明确删除证据才会判为已失效。
8. 本机代理、直连和公开云线路都无法连接目标，且同站对照也不健康时，访问层记为“自动多线路不可访问”；内容状态仍是“未知”，合同建议是“待独立普通网络复核—尚不能归责供应商”。
9. 点击“重试访问异常”时只重跑暂时异常记录；自动多线路不可访问进入独立普通网络抽样清单，不通过无休止刷新来制造结论。


六、结果含义
------------

已失效：取得了目标内容当前已经删除、不存在、下架、私密不可见或进入已验证错误页的强证据。

仍可访问：当前页面、官方内容页或可靠公开接口能够确认目标内容编号及正文/摘要/作者等身份，目标内容仍存在。

自动多线路不可访问：本机系统代理、直连和公开云线路均未取得目标正常页面或正文。它只能证明当前自动取证环境没有取得内容，不能证明内容删除，也不能单独证明供应商违约。

暂时异常：本轮所有已配置取证线路仍未取得正文或明确删除证据。结果会同时记录追证阶段、取证线路、同站对照和共享基础设施，可一键重试。

人工复核：自动证据不足、证据冲突、需要登录/App、通用网页外壳或未知平台暂时无法自动确认。

“人工复核”不等于已失效，也不等于仍可访问。

AI 辅助复核是可选的二次阅读层，不单独把网络失败猜成删除。表格中的“AI建议”用于审计模型意见。

写回 Excel 时写入三列：“链接是否失效”“公开可访问性”“合同验收建议”：
- 已失效 -> 是
- 仍可访问 -> 否
- 自动多线路不可访问 -> 待独立复核
- 人工复核 -> 待复核


七、Excel 写回与结果保存
----------------------

1. 工具核验过程中不会自动修改原 Excel。
2. 写回前请关闭 Excel 中正在打开的原文件。
3. 写回前会在原文件同目录创建“文件名_核验前备份_时间.xlsx”。
4. 如果原 Excel 所在目录不可写，写回会失败，需要把文件移动到有权限的位置。
5. 直接粘贴链接、导入 TXT 或仅需独立结果时，使用“导出结果”保存 CSV。
6. 超过 5,000 条时，界面只显示性能模式允许的前一部分记录；断点、写回和导出仍包含全部结果。
7. CSV 导出会保留内容状态、公开可访问性、合同验收建议、证据等级、供应商行动、AI 审计、取证线路、同站对照和基础设施分组。
8. 验收证据包包含完整业务链接、方法说明、待补证清单、独立普通网络复核清单和 SHA-256 清单；发送给供应商前按单位数据管理要求处理。


八、性能模式
------------

自动适配：根据进程位数、CPU 核心数和物理内存选择保守并发，并对容易触发安全验证的平台按域名限速。建议保持此选项。

低配模式：1 个并发、较小页面读取量、较少表格显示行，适合低配置电脑、单位网络或已经出现平台风控时使用。

标准模式：3 个并发，适合常见办公电脑。

高性能模式：6 个并发，只适合配置较高且平台分布较分散的任务。单位网络限速或站点风控明显时，不建议使用。

工具会把同一平台的请求按最短间隔排队，HTTP 429 不会立即换线路重试；深度复核一旦看到安全验证、访问频繁或验证码，会暂停本批该平台的剩余链接。暂停项不会丢失，可在平台冷却后继续。即使使用高性能模式，也不会绕过验证码或平台安全机制。


九、常见问题
------------

1. 双击后没有主界面
   查看“启动检查报告.txt”。若报告提示文件缺失、.NET 版本过低或从压缩包临时目录运行，按报告处理后重试。

2. 所有 HTTP/HTTPS 都显示连接失败
   双击“运行环境与网络诊断.cmd”。报告会分别测试系统代理和直连。若两条路线都被拒绝，通常是安全软件、代理白名单或单位网络策略，不是失效识别规则问题。

3. 快速核验能用，深度复核打不开
   查看启动检查报告中的“Edge WebView2 Runtime”。未检测到时安装或修复 WebView2 Runtime。

4. Excel 写回失败
   关闭 Excel，确认文件不是只读，确认所在目录有写权限后重试。

5. 某个平台突然大量进入人工复核
   可能是平台改版、接口变化、验证码、账号风控或网络拦截。不要把这批记录直接视为已失效，请保留结果和诊断报告用于更新规则。

   “自动多线路不可访问”“访问异常待重试”和“其他待补证/复核”分开显示。前者不会算作内容状态已确认，而会进入独立普通网络复核清单。只有已经取得正文但机器规则证据不足的记录才发送给 AI。

6. 程序异常退出
   工具会在用户数据目录或桌面生成“运行异常报告_时间.txt”。重新打开后先点击“继续上次核验”，再把报告交给维护人员。

7. 怎么使用 Yunwu AI 辅助复核
   先点击“AI 设置”，在本机输入 Token，点击“读取模型”，选择一个支持 Chat Completions 的模型，再点击“测试并保存”。保存后，“开始核验”会自动处理全部符合安全条件的候选，不再限制每轮 100 条；“AI 辅助复核”按钮用于主动重跑剩余候选，手动启动时仍会显示发送数量和数据范围。

   单条 AI 请求失败会自动重试一次；仍失败时保留该条供下次继续，不会立刻中断整批。连续 3 条都失败时才暂停本批，避免网络异常、额度不足或限流继续消耗请求。Token、额度、API 地址或模型权限错误会立即停止并明确提示。

8. 为什么 AI 没处理某些人工复核
   网络异常、验证码、登录页、App 限制、403/429、页面摘要不足和已经确定的结果不会发送给 AI。旧版本断点没有保存页面摘要时，请用当前版本重新核验候选项。

9. AI 能不能解决网站风控
   不能。AI 只阅读工具已经取得的页面证据，不会绕过验证码、登录、平台权限或单位网络限制。遇到这些问题，应等待平台冷却、换用合规登录会话或由人工确认。

10. 为什么使用内置 WebView2，而不是随便选择一种浏览器
    深度复核需要程序稳定控制页面加载、读取正文、保留同一登录会话并逐条自动继续。WebView2 是 Windows WinForms 可直接嵌入和维护的浏览器运行时，Windows 10/11 通常已具备；它不等于强制你日常使用 Edge。

    快速核验仍会在可用时调用 Edge 或 Chrome 做少量无界面补证，手动“打开选中链接”则使用 Windows 默认浏览器。Chrome、Firefox 和其他浏览器不能直接替换 WebView2 的嵌入接口；同时维护多套自动化内核会显著增加兼容故障，却不能绕过平台验证码和权限限制。

11. 怎样把执行情况发给维护人员分析
    每次快速核验、浏览器快速复核、后台深度复核或 AI 辅助复核结束时，工具都会生成独立执行日志。点击主界面的“查看执行日志”会打开最新一份。

    日志包含工具版本、运行编号、开始/结束时间、执行结果、任务数量、结果和 HTTP 状态分布、平台/域名汇总、AI 请求/成功/失败/重试次数、关键执行事件、中断原因、匿名问题样本和自动诊断提示。

    日志不包含 API Token、Cookie、登录账号、完整网页正文或完整链接。问题样本使用匿名链接 ID，并对短原因中的链接、凭据、邮箱和用户目录做脱敏。发送前仍应按所在单位要求检查内容。

    默认日志目录位于当前用户数据目录的 LinkDispositionChecker\RunLogs；“最近一次执行日志.txt”始终指向最近结束的一次任务。历史执行日志最多保留 100 份。反馈时优先发送这个文件，并补充说明你认为最影响使用的现象。


十、数据安全
------------

工具在本地运行，不会把导入的工作簿或整批链接上传到本工具自己的服务器。
核验时会从当前电脑直接访问目标平台及其公开内容页/公开接口，这是完成核验所必需的网络访问。
启动检查报告不包含导入文件内容、待核验链接、Cookie、账号、密码、IP 或代理地址。

4.2 内置 Jina AI Reader 作为公开云取证线路。只有本机访问得到 502、超时、连接失败或其他临时失败时，工具才会把单条公开目标链接发送给该服务，并要求无缓存浏览器读取；不会发送工作簿、整批链接、Cookie、登录账号或浏览器凭证。该服务是第三方服务，其日志、隐私和服务规则由服务方负责。

“远程取证设置”默认为空，用于追加使用者或所在单位自有的 HTTPS 取证节点。配置后也只发送单条公开目标链接，不发送工作簿、Cookie、登录账号或浏览器凭证。自有节点的日志、隐私、合规和费用规则由节点运营方负责。

AI 辅助复核默认不启用。使用者主动配置后，开始核验会自动把合格候选的链接、标题、作者、HTTP 状态、机器判定依据，以及最多约 6500 字的当前可见正文摘要发送到所配置的 Yunwu API。不会发送 Cookie、登录账号、浏览器凭证或完整 Excel。

API Token 使用 Windows 当前用户的数据保护机制加密，保存在本机用户数据目录，不写入程序目录、导出结果或 Git 仓库。Token 只能由同一 Windows 用户在本机解密。Yunwu 是第三方 API 服务，发送的数据会受其服务条款、隐私政策和账户计费规则约束；处理敏感或受保密要求的数据前，应先确认所在单位允许使用该服务。


十一、当前验证基线
----------------

真实办公批次：1521 条去重有效链接。
4.2.0 修正合同验收口径：过去 4.1 把 769 条“公网不可访问”计入明确结论，口径过宽。按内容状态重新计算，该批次真正确认的是已失效 8 + 正文仍在 724 = 732/1521，内容状态确认率 48.13%；769 条应为“内容未知、待独立普通网络复核”，不能仅凭自动线路失败归责供应商。4.2 新增双维状态、合同验收建议、分层抽样复核清单、环境与方法说明、SHA-256 清单和自动验收证据包。
4.1.0（历史口径）增加内置无缓存公开云取证并完整产出 1521/1521 条操作结果；当时报告的 98.68% 是“操作结果覆盖率”，不是内容状态确认率，也不是准确率。
4.0.0 将工具重构为自动追证流程：按 DNS/IP 识别共享基础设施并统一限速；502、超时和连接失败后自动清理分享参数、进行同站首页对照并调用可选远程取证节点；同一基础设施连续异常时为剩余链接生成完整结果，不再静默跳过；浏览器复核和已配置的 AI 自动收尾；CSV 与执行日志新增追证阶段、取证线路、站点健康和基础设施字段。
3.16.0 增加独立的“重试访问异常（数量）”按钮，可重试暂时异常和上次因站点连续异常而未处理的链接；把“网络待重试/网络风控”改为更准确的“访问异常待重试”，明确区分代理、线路、目标服务器异常与真实平台限流；内置浏览器识别“当前无法使用此页面 / HTTP ERROR 502”等浏览器错误页，不再把它们送入人工或 AI 复核。
3.15.0 修复平台分享短链跳转后仍按原短链核验、导致头条等可确认内容落入人工复核的问题；站点连续受限后不再把整批显示成自动中断，改为明确记录已处理数量和“网络待重试”数量；网媒类暂停记录精确显示具体域名，稍后可从断点只重试未处理链接。
3.14.0 修复 AI 单条失败导致整批终止的问题，增加单条重试、连续失败暂停和失败后可继续；把“网络待重试”和“证据待复核”拆成独立统计及筛选；界面统一改称“内置浏览器复核”并解释 WebView2 的选择理由；执行日志增加 AI 请求/重试/失败和关键事件，并将历史日志限制为 100 份。
3.13.0 建立可重复的执行日志与版本迭代闭环。快速核验、浏览器复核、后台复核和 AI 复核结束后自动记录运行编号、结果分布、网络/平台状态、AI 使用、中断原因和匿名失败样本，并在主界面提供“查看执行日志”。

3.10.6 增加平台级请求排队、保守并发、HTTP 429 停止即时重试，以及安全验证后的同平台批次暂停，以减少连续批量核验触发风控。
3.10.5 当前网页基线：已失效 624、仍可访问 519、人工复核 57，人工复核率 4.75%。

这个 4.75% 是固定样本在 2026-07-24 的“人工复核比例”，不是对所有未来数据承诺 95.25% 准确率。平台、网络环境、链接类型和网页状态变化都会影响实际结果。
