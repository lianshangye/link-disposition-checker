链接失效检测工具 - 核验逻辑
============================

适用版本：4.4.2

一、唯一目标
------------

判断当前链接是否还能取得目标内容。

输出只有三种：

- 有效
- 失效
- 未完成

二、有效
--------

满足以下任一可靠证据：

- 当前原地址返回正常页面，并取得有效标题以及正文摘要或正文结构。
- 平台公开内容接口返回与目标内容编号一致的正文数据。
- 经过浏览器渲染后取得与目标链接一致的正文。

普通首页、空壳页、登录页、验证码页和 HTTP 200 错误页不能判定有效。

三、失效
--------

满足以下任一明确证据：

- 当前目标平台的最终地址返回 HTTP 404 或 410；跨站跳转或登录页返回 404/410 不直接判失效。
- 当前页面明确显示文章不存在、内容已删除、作品已下线等。
- 平台公开接口明确返回目标内容不存在。

四、未完成
----------

以下状态均为未完成：

- HTTP 403、429、444、5xx
- 超时、连接失败、DNS 或 TLS 异常
- 验证码、登录限制、App 强制打开
- 外部探针额度不足
- 页面有响应但无法确认目标正文

未完成项始终保留在续检队列。

五、检测顺序
------------

1. 原地址普通请求。
2. 清理分享和统计参数后重试。
3. 同站首页健康对照。
4. 中国普通宽带防火墙会话。
5. Cookie 更新后同探针重试。
6. 为当前链接重新建立全新会话。
7. 公开云浏览器取证。
8. 必要的内置浏览器渲染。

任何阶段取得正文或明确失效证据后立即结束该链接。

六、批量策略
------------

- 按域名连续处理，复用站点 Cookie 会话。
- 502 不触发域名或共享 IP 整组跳过。
- 只有目标站点直接返回 403、429、444 或明确安全验证时，才允许短暂保护性暂停该域名。
- 外部探针 429 只表示探针容量不足，不表示目标链接不可访问。
- 规则版本升级时会重跑受影响的旧结论；4.4.2 会重跑更早版本的结论，当前版本断点保留已确认的有效和失效，其他结果进入续检。

七、界面和导出
--------------

主界面只展示链接检测所需信息：

- 状态
- HTTP
- 页面标题
- 原链接
- 最终地址
- 检测说明
- 检测时间

CSV 和 Excel 写回也只输出链接状态、HTTP 状态和页面标题等检测字段。

八、断点可靠性
--------------

- 任务身份由工作表、行号和 URL 共同组成；同一行换链接不会沿用旧结果。
- 主进度、备份和追加日志共同恢复已完成记录。
- 日志最后一行因断电或强制退出损坏时，忽略该残行并保留此前完整结果。
- 用户关闭程序时先停止任务、接收队列中最后一批结果并保存，再真正退出。
